# Classification and optional suggestions

dolphino applies manual corrections/splits first, then merchant rules and useful provider categories. Accepted AI categories sit below these sources and remain separate from manual overrides with an audit entry. Unchanged provider refreshes preserve an accepted AI category; substantive source changes invalidate it. Transfers and ambiguous source-identity/kind reviews are never automatically classified.

Use administrator **Settings → Optional AI classification** to choose OpenAI or Amazon Bedrock, enter the model and required write-only credentials, set request/batch limits and explicitly enable classification. Bedrock also requires a supported AWS region. Choose a small inexpensive model supporting the provider contract. No provider is configured by default. Credentials are encrypted in PostgreSQL and never enter settings responses or job records. OpenAI and Bedrock use fixed secure endpoints. Legacy integration environment values are ignored, with no silent import or fallback; existing environment-only users must re-enter their configuration in Settings. Saving configuration needs no live provider call and takes effect without a restart.

When classification and automatic suggestions are both enabled, the background worker checks every 30 seconds and automatically queues unresolved posted transactions, including previously imported unresolved records. Turning off **Automatically suggest categories for unresolved imports** disables scanning and pauses existing automatic jobs; on-demand suggestions remain available while the master **Enable AI classification** switch stays on. Turning off the master switch pauses both paths without removing credentials, jobs or suggestions. Pending transactions, existing manual corrections, matching rules, useful provider categories, internal transfers and ambiguous reviews bypass automatic AI work. Successful suggestions remain in the review workflow and can be retrieved using the transaction editor's suggestion action.

**Automatic application is disabled by default.** Explicitly enable **Automatically apply validated category suggestions** in Settings to permit applying automatic-job suggestions. Categories must belong to the configured category list and must not be `Uncategorized`. Under the same database lock used for ledger mutations, dolphino rechecks the source evidence, eligibility, rules, provider category and manual overrides. Stale or unresolved suggestions fall back to review without replacing those classifications. Accepted AI classification recalculates persistent budget alerts in the same transaction. On-demand jobs always return a suggestion for review.

There is no age limit on that scan, so a separate bulk reclassification action is unnecessary for genuinely unresolved imported history. Redbark taxonomy references must first resolve to names (or become Uncategorized when no name is available); an opaque reference is not a useful category. Useful resolved provider categories still take precedence. Financial-kind/transfer and source-identity reviews remain excluded: the model suggests only a category and cannot decide whether money is income, spending, a refund or an internal transfer. Changing the automatic-application switch does not reapply already-successful cached suggestions; accept those individually in the editor. Manual corrections remain protected.

Only the first 120 description characters (long digit sequences redacted) and available category labels are sent. The model receives no amount, date, account identifier, bank balance, or transaction ID. Merchant descriptions and custom category labels may still be sensitive; configuring a provider permits sending these selected fields. Requests use a 15-second timeout and a 150-output-token limit. Financial values remain local even though they participate in job deduplication fingerprints.

Jobs persist in PostgreSQL and are keyed by mode, canonical transaction ID, and a fingerprint of source fields, category list, endpoint, model and a one-way credential digest. Concurrent workers share jobs and serialize provider calls (concurrency one across application instances using the same database/schema and mode). **Maximum import batch** defaults to 5 jobs per tick (range 1–20). **Requests per UTC day** defaults to 20 attempts per UTC calendar day (range 1–1000), shared by manual and automatic requests and all instances. Reservations are persisted before network I/O; failures and process crashes consume the allowance. This bounds request counts, not a guaranteed monetary price; provider pricing remains the operator's responsibility. Exhausted daily allowance leaves work pending until the next UTC day.

Pending jobs survive restarts and retry with exponential delays starting at one minute, honoring `Retry-After`, for at most five attempts per retry cycle. Errors persist a fixed safe code, never response bodies or credentials. The automatic scanner never resets failed jobs. Explicitly using the editor's suggestion action retries a failed job with a new bounded cycle, subject to the same daily limit. Configuration or substantive source changes create a fresh job identity. Successful suggestions are cached. Automatic acceptance applies only to automatic-origin jobs; an explicit request for a pending automatic job converts it to manual review.

Imported data, manual edits and budgets remain usable throughout provider downtime. Queue records, usage counters and audit history are included in full PostgreSQL backups. There is no bulk AI job-management UI or external alert delivery in this MVP; review and retry are per transaction.
